# /portfolio-check — 기술 문서 점검

대상: `$ARGUMENTS` (비어 있으면 `src/`의 모든 프로젝트)

기술 문서를 **쓰는 중에** 가이드 기준을 만족하는지 확인하는 명령입니다. `data/`·`src/`는 수정하지 않습니다.

## 순서

1. `format/01-portfolio.md`, `format/02-tech-document.md`, `format/03-diagrams.md`를 읽습니다.
2. 대상 프로젝트의 기술 문서를 끝까지 읽고, `images/`·`code/` 파일 목록을 확인합니다. 기술 문서를 고르는 규칙은 `/portfolio-build` §1과 같습니다(폴더 바로 아래의 `.md`, `_intake/`는 읽지 않음).
   루트 `.md`가 없고 `_intake/`만 있으면 점검하지 않고 "아직 재료집 단계입니다. 재료집 질문에 답해 `기술문서.md`를 직접 쓴 뒤 다시 실행하세요"라고 리포트합니다.
3. 판정합니다.
   - 문서 유형(A 단일 기능 / B 다기능 / C 팀)을 먼저 정하고, 그 유형의 흐름으로 봅니다. **제목이 아니라 내용**으로 판정.
   - 5단계마다 `format/02`의 체크 항목을 확인 → **필수 / 권장 / 참고**로 분류.
   - `format/02`의 **'있으면 좋은 항목'**(레퍼런스, 핵심 루프, 조작법, TO-BE, As-Is/To-Be)은 **참고**로만 봅니다.
     제목이 아니라 **내용**으로 판정합니다(예: "원작과 다른 점"을 설명한 문단도 레퍼런스로 인정, 조작 표가 있으면 조작법으로 인정).
     없다고 해서 요약 표의 필수·권장 개수에 넣지 않고, 프로젝트별 점검에 **[참고]**로 한 줄만 적습니다.
   - 상세 페이지 항목(`format/01` §2): 개발 환경·링크·스크린샷 4~6장(기술 문서 안의 이미지 수로 셈)·선택 이유·이슈 해결 사례.
   - 다이어그램(`format/03`): 시스템 구조에 1개 이상, 요약 수준, 캡션.
   - **발표 덱 대비(추정, md만 보고)** — 발표 덱(`project.html`)은 16:9 장면이라 큰 그림과 긴 코드가 작아지거나 나뉩니다. 실제 크기는
     `/portfolio-build`의 미리보기 점검이 재므로, 여기서는 **참고**로 미리 알려 줍니다:
     - mermaid 블록마다 노드 수와 `TD`(세로) 방향의 단계 수를 셉니다. 노드가 10개를 넘거나(`format/03` "10개 이하 권장") 세로로 길면
       "[참고] §3.2 다이어그램은 노드 14개 · 세로 7단계라 발표 덱에서 글자가 작아질 수 있습니다. 둘로 나누거나 `LR` 방향을 생각해 보세요".
     - 코드 블록 중 20줄(펜스 제외)을 넘는 것의 수를 셉니다. "[참고] 20줄을 넘는 코드 블록이 3개(§4.3 34줄, …)라 발표 덱에서 두 장면으로 나뉩니다.
       상세 문서에는 전체가 남으니, 덱에서 보일 핵심 부분이 어디인지 알아 두면 좋습니다".
   - 문서 속 이미지 경로가 실제 파일과 **대소문자까지** 맞는지, 링크가 `#`·빈 값이 아닌지.
   - `code/`가 있으면 문서 코드의 주요 클래스·메서드 이름이 실제 코드에 있는지 표본 확인.
4. `report.md`에 씁니다. `/portfolio-build`의 리포트 형식에서 **"확인해 주세요"·"장면 점검" 섹션을 빼고** 같은 형식을 씁니다
   ([../portfolio-build/SKILL.md](../portfolio-build/SKILL.md) §6 — 요약 표의 **참고** 열 포함). 기존 report.md는 덮어쓰되,
   기존 report.md에 `## 확인해 주세요` 절이 있으면 그 절은 **그대로 옮겨 둡니다**(빌드·`/portfolio-edit`가 남긴 Claude 압축 문장 기록, 원칙 3).

## 피드백 쓰는 법

- 항목마다 **어디가(섹션) / 무엇이 부족하고 / 왜 중요한지(기준) / 어떤 방향으로** 를 한 줄씩.
- 👍 잘한 점도 프로젝트마다 1~2개 짚어 줍니다 (무엇을 유지해야 하는지 알 수 있게).
- **고친 문장을 대신 써 주지 않습니다.** 예시가 꼭 필요하면 `format/` 의 👎/👍 예시를 가리킵니다.
- 빠진 다이어그램은 `format/03-diagrams.md`의 프롬프트 틀을 채운 **요청 문장**으로 제안합니다.
- 마지막에 대화창으로 프로젝트별 필수 개수와 가장 먼저 고칠 1가지를 짧게 알려 줍니다.
