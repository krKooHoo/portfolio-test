# /portfolio-intake 출력 형식

재료집·촬영목록은 아래 형식을 그대로 씁니다. `<…>`만 채우고, 해당 내용이 없으면 그 행을 지우지 말고 "없음(근거)"이나 ❓로 둡니다.
**서술문은 안내 문구(이 파일에 있는 문장)만** 씁니다. 기능을 설명하는 문장은 쓰지 않습니다.

## `_intake/재료집.md`

바깥 펜스(````)는 이 설명 파일의 표시용입니다. 재료집에는 그 안쪽만 씁니다.

````markdown
# <productName 또는 레포 이름> — 재료집 · 질문지

> ⚠ 이 파일은 **기술 문서가 아닙니다.** 코드와 커밋 기록에서 확인한 사실과, 여러분만 답할 수 있는 질문입니다.
> 질문에 답하면서 `../기술문서.md`를 **직접** 새로 쓰세요. 이 파일을 그대로 옮기거나 이름만 바꾸면 안 됩니다.
> 이 폴더(`_intake/`)는 git에 올라가지 않습니다. 기술 문서를 다 쓰면 지워도 됩니다.
> 출처: <url> @ <SHA 7자리> (받은 날 <YYYY-MM-DD>) · 자세한 점검: `report-intake.md`

| 표시 | 뜻 |
|---|---|
| ✅ 사실 | 코드·설정·커밋에서 확인. 괄호 안이 근거(`경로:줄` / 커밋 해시) |
| ❓ 질문 | 여러분만 답할 수 있음. 답이 기술 문서의 본문이 됩니다 |
| ⚠ 추정 | Claude의 해석. 맞는지 확인하고, 틀리면 버리세요 |
````

## `_intake/촬영목록.md`

```markdown
# <이름> — 촬영 목록

> `src/<NN-이름>/images/` 폴더를 만들고 아래 화면을 찍어 넣으세요. 기능이 겹치지 않게 **4~6장**이 좋습니다.
> 파일 이름은 영문 소문자를 권장합니다(예: `boss_intro.gif`). 기술 문서에는 `![설명](images/파일이름)`처럼 상대경로로 넣습니다.
> 영상은 파일로 넣지 말고 YouTube 등에 올려 **링크**로 쓰세요(5분 이내, 편집 원본은 보관).
> (팀 프로젝트) 내가 맡은 기능이 보이는 화면을 먼저 찍으세요.

| # | 보여 줄 화면 | 들어갈 절 | 종류 | 권장 파일 이름 | 근거 |
|---|---|---|---|---|---|
| 0 | 대표 화면(타이틀 또는 가장 인상적인 장면) | 개요 | PNG | `images/cover.png` | 포트폴리오 문서 프로젝트 소개·발표 덱 표지에 크게 나옴 |
| 1 | <식별자 명사구 — 예: `BlockType.Bomb` 사용 장면, 씬 `Boss` 진입> | 3. 핵심 기능 | GIF 10초 이내 | `images/<기능>.gif` | ⚠ `<파일:줄>`·씬 `<이름>`에서 추정 |
| … | | | | | |
| V | 시연 영상 | 개요 표 링크 | 링크 | (파일 아님) | 구간은 `?t=초` |

용량(⚠ 제안값): PNG는 1280×720 이상·2MB 이하, GIF는 폭 960 이하·10초·8MB 이하, 프로젝트 `images/` 합계 60MB 이하. GitHub는 파일 하나가 100MB를 넘으면 올리지 못합니다.
```
