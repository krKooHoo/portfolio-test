# /portfolio-edit — 발표 덱 장면 고치기

요청: `$ARGUMENTS` (비어 있으면 대화에서 프로젝트·장면·요청을 찾고, 모자라면 묻습니다)

시작 전에 `CLAUDE.md`의 **반드시 지킬 원칙**을 다시 확인합니다. 형식은 [schema.md](../portfolio-build/schema.md) 「장면 고치기 파일」과 「발표 덱 `deck`」.
고친 결과는 `src/<폴더>/deck-edits.json`(수강생 소유)에 쓰고, 적용 스크립트 `.claude/skills/portfolio-build/deck-edits.py`가 `data/`에 반영합니다.
**data JSON을 손으로 고치지 않습니다**(스크립트만). 기술 문서(`.md`)는 이 명령에서 **절대 고치지 않습니다**.

스크립트(레포 루트에서, `python`이 없으면 `py`):

| 명령 | 하는 일 |
|---|---|
| `python .claude/skills/portfolio-build/deck-edits.py show <폴더> <장면>` | 그 장면의 지금 JSON과 빌드 원래 JSON(묶음 `group`도) |
| `… pin <폴더> <장면>` | 장면을 고치기 파일에 통째로 고정(닻 `from`을 채움) → 그 pin을 Edit로 고침 |
| `… pin <폴더> <장면> --as <새 key>` | **나누기**: 원래 장면도 고정하고 복제본을 바로 뒤 새 장면으로. 두 pin은 한 묶음(`group`) |
| `… add <폴더> <새 key> --after <장면>` | **새 장면**: 그 장면 바로 뒤(같은 장)에 빈 장면. 필드를 모두 채워야 반영됨 |
| `… hide <폴더> <장면>` | 숨기기 |
| `… hide <폴더> <장면> --into <남길 장면>` | **합치기**: 남길 장면도 고정하고 이 장면을 숨김. 두 항목은 한 묶음 |
| `… undo <폴더> <장면>` · `… undo <폴더> --all` | 그 장면의 고친 것 지우기(**같은 묶음도 함께** — 나누기·합치기는 둘 다 원래대로) · 전부 |
| `… apply <폴더>` | data에 반영(pin·add·hide·undo 뒤에 **반드시**). `check`는 쓰지 않고 결과만 |

`<장면>` 자리에는 key, `d-spawn-weight`, `#s=d-spawn-weight`, 나뉜 장면 주소(`d-spawn-code-2`·`d-pool-t1`)도 됩니다.
출력의 `[필수]`가 있으면 반영하지 않은 것이 있다는 뜻입니다(종료 코드 1). `[권장]`의 "지문이 다릅니다"는 원문 블록 참조가 틀린 것이라 미리보기에 빨간 띠가 생깁니다 — 원문 지문으로 고칩니다.

## 1. 먼저 확인

- `python`·`py`가 모두 없으면 멈추고 Python 3.8 이상 설치를 안내합니다(python.org, 설치 화면의 'Add python.exe to PATH' 선택 → Claude Code 다시 시작). **data JSON을 손으로 고쳐 대신하지 않습니다.**
- `data/projects/<폴더>.json`에 `deck`이 없으면(예전 데이터, 덱에 노란 "자동 구성" 띠) 멈추고 "먼저 `/portfolio-build <폴더>`"를 안내합니다.
  data의 `doc`이 가리키는 기술 문서가 없을 때(문서 이름을 바꿈)도 같습니다.
- 포트폴리오 문서(`index.html`, 아래로 읽는 페이지 — 장면이 아님)의 대표 이미지·기능 소개는 이 명령으로 고치지 않습니다. 이미 있는 방법을 안내합니다: 대표 이미지는 기술 문서에 "대표 이미지"로 지정, 프로젝트 순서는 `profile.md`, 기능 설명은 기술 문서 → 다시 빌드.

## 2. 분류 — 내용 문제인가, 배치 문제인가

| 요청 | 할 일 |
|---|---|
| 사실·수치·설명이 틀림, 설명을 더 넣고 싶음, 다이어그램·코드 **내용**을 바꾸고 싶음, 장 제목을 바꾸고 싶음, 원문에 없는 문장을 넣고 싶음 | **고치지 않습니다.** "기술 문서 §n을 고친 뒤 `/portfolio-build <폴더>`"라고 어느 절인지와 방향만 알려 줌(원칙 2·4). 문장을 대신 써 주지 않음 |
| 장면 틀, 원문의 어느 그림·코드·표를 보일지, 코드 줄 범위, 나누기·합치기·숨기기·순서, 탭, 제목 줄이기, 도입·요점을 원문의 다른 문장으로 바꾸기·줄이기 | 장면 고치기(아래) |

- 불평이나 감상("이 장면 좀 비어 보여")은 바로 고치기 요청으로 읽지 않습니다. 무엇을 바꿀 수 있는지 장면 카드로 보여 주고 고를 수 있게 합니다.
- 글 조각은 **원문 그대로**(`verbatim: true`) 또는 **Claude가 줄인 것**(`verbatim: false`)만 씁니다. 수강생이 직접 친 문장도 원문 그 절에 같은 글자가 있을 때만 받고, 없으면 "기술 문서에 먼저 적고 다시 빌드"로 안내합니다.

## 3. 장면 찾기

1. **`#s=` 주소**(배포 화면이든 미리보기든 주소창에서 복사) → `d-<key>`가 곧 장면입니다. 가장 확실하므로 모호하면 이 방법을 권합니다.
2. **제목 일부** → `deck.slides[].title.text`·`sectionPath`에서 찾고, 둘 이상이면 후보를 보여 주고 묻습니다.
3. **N번째 장면** → 번호는 렌더러가 만든 장면(표지·목차·장 표지·회고·맺음, 나뉜 코드 장면)까지 센 것이라 미리보기에서 바꿔야 합니다:
   `project.html?p=<폴더>`에서 `await PFScene.whenReady(); PFScene.report().ids[N-1]`(브라우저 도구가 없으면 `CLAUDE.md` 「미리보기」의 headless 방법).
   미리보기의 **개요(▦)** 격자에는 장면마다 id가 보입니다.
- `d-`로 시작하지 않는 장면(`cover`·`toc`·`ch-…`·`retro`·`end`)은 고칠 수 없습니다 — 무엇이 거기서 오는지 알려 줍니다(장 표지 = 그 장의 장면 목록, 회고 = 기술 문서 회고 절).
- 코드가 나뉜 `d-<key>-2`·표가 나뉜 `d-<key>-t1`은 `d-<key>` 장면입니다.

## 4. 장면 카드 → 확인

`show`로 지금 장면을 읽고, 기술 문서에서 그 장면의 절 범위(`sectionPath` 마지막 제목부터 다음 제목 전까지)를 **직접 읽어** 아래를 쉬운 말로 보여 줍니다.

- 지금: 틀(`layout`), 탭, 제목, 도입·요점(원문 그대로/줄임), 시각 자료(무엇인지: "§4.3의 표 1 '레벨|지수'", "§2.1 다이어그램")
- 그 절에 있는 다른 원문 블록(종류별 번호 `n`과 지문 — [schema.md](../portfolio-build/schema.md) 「원문 블록 참조」 그대로: 코드는 첫 비어 있지 않은 줄 60자,
  mermaid는 `%%`로 시작하는 지시 줄(`%%{init…}%%`)을 **건너뛴** 첫 줄 60자, 표는 머리 칸 글자를 `|`로 이은 것) — 원하면 상위·형제 절 블록도(참조마다 `sectionPath`).
  지문을 잘못 적으면 `apply`가 `[권장] … 지문이 다릅니다 — 원문 "…"`으로 알려 주니 그 글자로 고칩니다.
- 쓸 수 있는 틀: `overview` 글 중심 · `visual` 그림 + 번호 카드 · `code` 코드 + 설명 · `full` 큰 그림·표 하나 · `screens` 화면 2~3장 · `problem` 문제 → 원인 → 해결 → 결과
- **고친 뒤 모습**과 영향: 장면 수(30장 넘으면 알림), 포트폴리오 문서 기능 소개의 [발표 덱에서 보기]가 이 장면으로 연결되는지(숨기면 그 장의 장 표지로 감), 공유했던 `#s=` 주소(숨기면 같은 절의 남은 장면 → 장 표지로 넘어감).
  장에 하나뿐인 장면을 숨기면 그 **장 표지와 목차 항목도 사라집니다**(기능 카드·주소는 발표 덱 표지·목차로).
- 되돌릴 수 있다는 것과, 그 장면의 **기술 문서 절 제목을 바꾸면** 다시 빌드 때 고친 내용이 풀린다는 것(다시 고치면 됨)
- 효과가 없거나 거꾸로인 변경은 미리 말합니다:
  - 세로로 긴 다이어그램(시퀀스·위→아래 흐름도)은 `full`로 바꾸면 **더 작아집니다**(아래 카드 줄이 높이를 먹음). 다이어그램을 둘로 나누는 것은 기술 문서 쪽 일입니다.
  - 표만 있는 장면은 틀을 바꿔도 표가 원래 크기보다 커지지 않습니다(빈 공간이 남음) → 옆 장면과 합치기를 권함.
  - 미리보기 참고 지표(`low-fill`·`tiny-diagram`)의 `detail` 괄호에 원인이 있습니다. 고치기로 나아지는지는 [/portfolio-build SKILL](../portfolio-build/SKILL.md) §7-1 「원인별 안내」 표를 따릅니다.

그다음 **"이렇게 고칠까요?"** 로 묻고, 수강생이 **네**라고 한 뒤에만 파일을 씁니다(원칙 2). 여러 장면이면 한꺼번에 보여 주고 한 번에 확인받아도 됩니다.

## 5. 쓰기 — 연산별

모든 연산은 스크립트로 시작하고(`pin`·`add`·`hide`), pin의 필드는 Edit 도구로 `src/<폴더>/deck-edits.json`에서 **그 pin만** 고칩니다. `from`·`group`은 손대지 않습니다.

| 요청 | 방법 |
|---|---|
| 틀·탭 바꾸기 | `pin` → `layout`·`tab` |
| 그림·코드·표 바꾸기/빼기/더하기 | `pin` → `visuals`(0~3개, 원문 블록 참조만: `kind`·`n`·`fp`·(코드)`lines`·(이미지)`src`·`w`·`h`·`caption`, 다른 절이면 `sectionPath`). `visual`·`code`·`full`은 1개 이상, `screens`는 이미지 2~3개 |
| 코드 줄 범위 | `pin` → 그 코드 참조의 `lines: [시작, 끝]`(펜스 제외 1부터). 20줄을 넘으면 렌더러가 "계속" 장면으로 나눔 |
| 글 줄이기·원문 다른 문장으로 | `pin` → `title`·`lead`·`points[]`. 원문 글자 그대로면 `verbatim: true`, 줄이거나 합쳤으면 `false`. `lead`는 80자, 요점 90자 안팎 |
| 나누기 | `pin <장면> --as <새 key>` → 두 pin의 `visuals`·`points`를 나눔(새 key는 `^[a-z][a-z0-9-]{1,31}$`, 예: `spawn-weight-code`). 새 장면의 `title`은 원래 그대로 두거나 원문 하위 제목으로. 요점이 없는 장면은 시각 자료가 가로 전체로 그려짐 |
| 합치기 | `hide <없앨 장면> --into <남길 장면>` → 남길 장면 pin에 없앨 장면의 `visuals`·`points`를 옮겨 넣음(시각 자료 3개, 요점 4개까지). **넘치면** 어느 것을 남길지 장면 카드에서 수강생에게 묻고, 줄여 합치는 것은 수강생이 그쪽을 고를 때만(`verbatim: false`) |
| 숨기기(빼기) | `hide` |
| 순서 | `pin` → `after: "<같은 장의 key>"`. 장을 옮기려면 `chapter`(after가 없으면 그 장 끝) |
| 새 장면(빌드가 고르지 않은 절) | `add <새 key> --after <장면>` → `sectionPath`·`title`·`layout`·`visuals`·`points`를 그 절 것으로 채움(빈 채로 두면 `[필수]`) |
| 되돌리기 | `undo <장면>` — 나누기·합치기로 생긴 짝도 함께 원래대로(출력에 "같은 묶음: …도 함께") · `undo --all` |

그다음 `apply <폴더>`. 출력 처리:
- `[필수]` → 그 장면은 반영되지 않았습니다. 원인(원문에 없는 verbatim 글, 규칙 위반 등)을 고쳐 다시 `apply`. 고칠 수 없으면 수강생에게 이유를 쉬운 말로 알림.
- `[권장]`·`[참고]`(지문 다름·고아·순서 못 옮김·겹쳐서 뺀 장면·기능 카드 연결·빈 장·장면 수) → 지문은 고쳐서 다시 `apply`, 나머지는 수강생에게 알림.
- "확인해 주세요" 줄(이미 리포트 형식) → §7의 report.md에 글자 그대로.

## 6. 미리보기로 확인

`project.html?p=<폴더>#s=<장면 id>`를 열어(이미 떠 있으면 새로고침) `await PFScene.whenReady()` 뒤 `PFScene.report()`에서 **그 장면**(과 나뉜 장면)의
`audit`(잘림·`visual-*`)과 `info.notes`(채움률·다이어그램 글자)를 봅니다. 브라우저 도구가 있으면 장면 캡처를 보여 줍니다.
- `visual-missing`·`visual-ambiguous`·`visual-changed`가 그 장면에 있으면 참조(`sectionPath`·`n`·`fp`)를 고쳐 다시 `apply` → 0건이 될 때까지.
- `clipped`면 시각 자료·요점을 줄이거나 나누기를 제안합니다.

## 7. report.md 기록과 마무리

- `report.md`가 있으면 `## 확인해 주세요`(없으면 이 절을 만듦)에 스크립트가 낸 줄을 글자 그대로 더하고(같은 장면 id의 줄이 있으면 바꿈),
  `## 장면 점검`의 그 장면 항목을 새 결과로 바꿉니다. 숨기기·나누기로 그 덱의 **장면 번호가 바뀌었으면** 그 덱 항목들의 번호를 `report().ids`로 다시 매기고
  덱 머리의 장면 수와 `## 요약` 표의 개수도 맞춥니다.
  `report.md`가 없으면 `# 포트폴리오 점검 리포트 (YYYY-MM-DD) — 장면 고치기 기록` 아래 두 절만 만들어 씁니다.
  빌드 없이 push해도 Claude가 줄인 문장이 기록에 남게 하기 위해서입니다(원칙 3). 그 문장은 고치기 파일에 `verbatim: false`로 남아 있어 다음 빌드·고치기 때도 다시 나옵니다.
- 짧게 보고합니다: 무엇을 고쳤는지(장면 id), 미리보기 주소, 남은 `[권장]`, "확인해 주세요" 줄, 되돌리는 법(`/portfolio-edit <폴더> <장면> 되돌리기` — 나누기·합치기는 짝도 함께).
- 고친 내용은 `src/<폴더>/deck-edits.json`과 `data/projects/<폴더>.json` **두 파일**에 있으니 둘 다 commit·push해야 배포에 보입니다.
