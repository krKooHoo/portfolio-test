# R0 결과

이 문서는 R0 검증 스파이크의 결과 기록입니다. 설계 문서([README](README.md), [01](01-scene-layout-print.md), [02](02-style-presets.md))가 정한 **통합 설계**를 R1을 만들기 전에 실제 샘플 데이터로 돌려 보고, 스파이크마다 채택·기각을 정합니다. 지금은 **A단계(A1 통합 시험대, A2 transform 배치, A3 인쇄 레시피 재시험, A4 준비 게이트)**까지 끝났고 B·C·D 단계는 예정입니다.

- **검증 대상**: 01 §6(분할기), §7-1(형제 + 여백 보정 transform), §7-2(`fit()` 단일 모드), §8-1(인쇄 레시피), §8-2·§8-3(준비 게이트와 작업 등록), §8-4(요약만 인쇄)를 합친 통합 설계입니다. 지금까지의 실측은 프로토타입 결과였고, 통합 설계 자체를 돌린 것은 이번이 처음입니다.
- **실험 환경**: Windows 11 Pro(10.0.26200), Chrome 155.0.8059.85, Edge 155.0.4283.62, Node v24.20.0, Python 3.12 + PyMuPDF.
  - 브라우저는 헤드리스로 띄워 CDP로 조종했습니다(`--remote-debugging-pipe`라 TCP 디버그 포트를 열지 않음).
  - 서버는 127.0.0.1의 스파이크별 포트(A1 4621, A2 4622, A3 4623, A4 4624)만 썼고, 끝난 뒤 모두 닫았습니다.
  - 실제 인쇄 대화상자는 A4 사례 5에서만 창 있는 브라우저로 열었습니다(미리보기 쪽 수만 확인).
- **시험대 위치**: `spikes/r0/`(커밋하지 않음). 레포의 렌더러(`index.html`, `project.html`, `assets/`)와 데이터(`data/`, `src/`)는 읽기만 했습니다. 실행 방법은 `spikes/r0/README.md`에 있습니다.
- **증거 파일**: 이 문서가 가리키는 `spikes/r0/out/...`은 `spikes/r0/.gitignore`로 빠져 있어 **이 PC에만** 있습니다(약 749MB).
- **판정 기준**: 01 §1-4 운영 정의 ①~④입니다.
  - ① 장면 안 잘림 0. 넘침은 조용히 잘리지 않고 이어짐 → 축소 → 눈에 보이는 잘림 띠 순서로 처리
  - ② PDF 쪽 수 = 장면 수, 모든 쪽 960×540pt, 빈 쪽 0, 브라우저 머리글·바닥글 0
  - ③ 장면 안 여백은 레이아웃 문제(채움률은 기록만)
  - ④ 그림·도식은 쪼개지 않고 축소(실효 글자 10px 미만은 권장, 10~12px은 참고)
  - 보장 범위는 Windows Chrome·Edge "PDF로 저장", 여백 기본입니다(Q1-b).
- **경로 차이 주의**: A단계 PDF는 거의 모두 CDP `Page.printToPDF`로 뽑았습니다. 보장 경로인 "PDF로 저장" 대화상자와 엔진은 같지만 같은 경로는 아닙니다. 대화상자에서 실제로 저장한 PDF 파일은 아직 검사하지 않았습니다(**미확인**).
- **수치 확인**: 각 스파이크 보고서의 숫자를 `spikes/r0/out/`의 요약 JSON·MD와 대조했습니다(무거운 실행은 다시 하지 않음). 보고와 다르게 읽힌 곳은 본문에 따로 적었습니다.
- **이 문서의 범위**: 결과만 기록합니다. **설계 문서는 아직 고치지 않았고**, 반영할 변경은 [설계 문서에 반영할 변경](#설계-문서에-반영할-변경아직-적용-안-함) 절에 모아 E단계에서 적용합니다.

### 설계보다 단순화하거나 뺀 것

아래 항목은 A2~A4 결과가 **보장하지 않습니다**.

- **빠진 기능**: 발표 모드·전체 화면, 브라우저 확대 보완안, 실행 중 넘침 감시(ResizeObserver)와 다시 나누기, `loadingdone` 늦은 글꼴 재분할(A4는 `project.js`를 다시 실행하는 방식으로 대신함), `selfTest()`·`flow()`·`fetchData()`
- **스타일 엔진 없음**: theme.css, 변형 축, `applyStyle`이 없습니다. 02의 스타일 계약은 시험하지 않았습니다.
- **원칙 5 ①**: 필드 경계에서만 나누고, 필드 안 줄 단위 분할은 하지 않습니다.
- **변형**: P1 "커버 없음 → 메타 2단", L2 `stack`이 없습니다.
- **안내·경고**: 회전 안내, 대체 글꼴·localhost 링크 경고가 없습니다.
- **이미지 크기**: `media` w×h가 data에 없어서(Q12 빌드 미구현) 이미지를 받아서 크기를 잽니다. 그래서 lazy가 대역폭을 실제로 아끼지 못하고, mount가 이미지 다운로드를 기다립니다(A4 사례 2에서 문제가 됨).
- **감사 범위**: `audit()`는 문서 단위 T1 항목(i×720 위치, 문서 높이·폭)을 하지 않습니다. 이 항목은 하네스의 `AUDIT_DOC`이 맡습니다.
- **경로**: 페이지가 `spikes/r0/pages/`에 있어 데이터 경로가 `../../../data`입니다(시험대 고유, 설계와 무관).

### 고친 CSS

**수정 1~3: 공유 키트에 반영함** (`spikes/r0/kit/scene-kit.css` 72~80행, ①의 §8-1 원문은 그대로 두고 ②에서 덮어씀. 모두 인쇄에만 영향)

**수정안 4: 설계 결정이 필요해 반영하지 않음** (`spikes/r0/a3/variants/scene-kit.deckonly.css`)

@media print {

### 새로 확인한 사실 (이전 미확인 해소)

- **printToPDF에서도 `beforeprint`·`afterprint`가 매번 실행됩니다**(인쇄 4회 → 4/4, Chrome·Edge). A1의 미확인 항목입니다.
- **`beforeprint`에서 바꾼 속성이 그 인쇄에 반영됩니다**(G1). ready = yes 뒤에 받는 중인 이미지를 붙이고 인쇄하면 키트의 beforeprint가 no로 바꿔 안내 1쪽이 나왔습니다. 실제 대화상자 경로는 A4 사례 5에서 확인했습니다.
- **[그래도 인쇄]는 인쇄마다 다시 켜야 합니다.** afterprint가 `data-pf-print-anyway`를 매번 지웁니다(T17c).

### 설계 공백 3건

1. **늦은 글꼴 재분할은 선택이 아니라 필수입니다.** 게이트의 `fonts.ready` 대기는 그리기만 지키고 분할은 지키지 못합니다(사례 4의 10초 차단). 01 §8-3 표의 "늦은 글꼴로 다시 분할"을 키트 훅이나 렌더러 필수 구현으로 못 박고, 다시 나눈 뒤 `data-pf-font=fallback`도 지워야 합니다.

3. **timeout 화면 안내와 [그래도 인쇄]는 Q12가 전제입니다.** 이미지를 받아서 크기를 재면 mount가 이미지 다운로드를 기다리므로, 느린 동안 HUD가 아예 없고 lazy도 대역폭을 아끼지 못합니다. Q12가 늦어지면 HUD를 mount 전에 만들어야 합니다.

## 남은 미확인과 다음 단계(B·C)

### A단계에서 남은 미확인

- **보장 경로 자체**: 실제 대화상자에서 저장한 PDF 파일(A단계는 printToPDF와 미리보기 쪽 수만 봄), 여백 최소·맞춤의 실제 PDF, Edge에서 설정 변경으로 미리보기를 다시 만드는 동작
- **배율·입력**: zoom 혼합(k ≥ 1.1, 01 §7-1 결정 2), 브라우저 확대(Ctrl ±) 상태의 화면과 인쇄, 부드러운 스크롤 경로, 실제 휠·트랙패드·터치·핀치, 실기기 DPR, 실기기 폰, 수정안 scroll 핸들러의 성능
- **시간**: 실제 네트워크·GitHub Pages(HTTP/2)와 차가운 CDN 캐시에서의 준비 시간(A1 수치는 루프백 + 따뜻한 캐시), 창 있는 브라우저의 백그라운드 탭·최소화 창 타이머 스로틀링, 대기 요청이 있을 때 printToPDF가 약 2초 늦어지는 원인
- **분할**: 짧은 장 이어 붙이기(샘플에서 0회), 실제 데이터에서의 원칙 5 경로(잘림 띠는 픽스처로만 확인), 글꼴 차단(T6) 전체 실행
- **기타**: `@page !important`끼리 앞 선언이 이기는 원인, Safari·Firefox(보장 밖)
- **단순화한 시험대가 다루지 않은 것**: 실행 중 넘침 감시와 다시 나누기, 스타일 엔진·변형 축(02), 발표 모드, `flow()`·`selfTest()`·`fetchData()`, custom 페이지

### 다음 단계(B·C·D)에서 다룰 R0 항목

번호별 범위는 R0 계획을 따릅니다. 아래는 설계 문서(README §5 R0 행, 01 §12 "R0 스파이크로 올린 미확인")에 남은 항목과 A단계가 넘겨준 조건입니다.

- **실제 대화상자 기본값 표**(Windows Chrome·Edge): 저장한 PDF 파일도 T2·T3로 검사합니다.
- **실제 기기 뷰포트 표**(Windows 100·125·150%, 즐겨찾기 막대, Edge 사이드바): 01 §2-3 표를 스크롤바 반영값으로 교체합니다(변경 #2).
- **확대(67~200%) 후 인쇄와 브라우저 확대 보완안 결정**(HUD 확대 버튼 / k 하한 유지): 안전 여백 16px의 효과도 잽니다.
- **헤드리스 PDF(실제 페이지)**: `--print-to-pdf` + `--virtual-time-budget`으로 CDN·글꼴·GIF가 있는 실제 페이지를 시험합니다.
- **학생 PC 장면 점검**(`?pf-audit=1` + `--dump-dom`): A4 사례 7의 조건(실제 시간 상한 + `ready` 확인)을 이어받습니다.
- **custom 통합 게이트**: React·Tailwind Play CDN 타이밍. mount 대기는 A4에서 고정 렌더러로만 확인했습니다.
- **Pretendard·D2Coding 로드**: dynamic-subset 결정, `local()` 설치본 차이. 변경 #21과 같이 봅니다.
- **zoom 혼합(k ≥ 1.1)**: A2에서 돌리지 않았습니다.
- (선택) Firefox, Paged.js
