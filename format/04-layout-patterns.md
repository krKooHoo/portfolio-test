## 패턴 → 고정 렌더러 매핑

| # | 패턴 | 이럴 때 | 고정 렌더러에서 | 데이터 |
|---|---|---|---|---|
| 1 | 문서 헤더 | 문서 첫머리 — 무엇에 대한 문서인지 | 랜딩 헤더 · 상세 히어로 | `profile`, `title`·`tagline` |
| 2 | 개요 (본문 + 요약표) | What/Why와 범위 | 상세 히어로의 메타 표 | `meta` |
| 3 | 본문 + 다이어그램 + 캡션 | 구조·흐름 설명 | 기술 문서 전문(라이브 Mermaid) | 원문 |
| 4 | 코드 + 설명 | 핵심 로직의 구현 증명 | 기술 문서 전문(하이라이트) | 원문 |
| 5 | 비교 표 + 결정 | 대안 비교·판단 근거 | 핵심 구현 카드의 "선택 이유" | `highlights[].why` |
| 6 | 콜아웃 / 노트 박스 | 핵심 원칙·주의 | 원문 인용문(`>`) 스타일 | 원문 |
| 7 | 절차 / 번호 목록 | 사용법·순서 | 원문 목록 스타일 | 원문 |
| 8 | 회고 서술 | 결과·배운 점 마무리 | 상세 "결과" 블록 | `results` |
| 9 | 스크린샷 + 캡션 | 실제 결과물 화면 | 상세 갤러리(4~6장) · 카드 커버 | `screenshots`, `cover` |
| 10 | 기술 스택 표 | 사용 기술·스펙 | 랜딩 "기술 스택" (경험 기반) | `skills` |
| 11 | 카드 그리드 | 병렬 항목 나열 | 랜딩 프로젝트 카드 · 핵심 구현 카드 | `projects`, `highlights` |
| 12 | 트러블슈팅 블록 | 버그·난관과 해결 | 상세 "이슈 해결" 블록 | `troubleshooting` |
| 13 | 타임라인 | 개발 과정·마일스톤 | (사용 안 함 — 원문에 있으면 원문으로) | 원문 |

## 레이아웃 원칙 (Part 3 요약)

- **한 화면 = 한 메시지.** 섹션마다 무엇을 보여주려는지 하나만.
- **다이어그램이 주인공**일 때는 넉넉한 여백 + 위 짧은 제목 + 아래 한 줄 캡션.
- 색은 **배경 / 텍스트 / 강조 3색 안에서** 통일. 강조색은 `profile.md`의 `강조색` 하나.
- 코드는 다크 블록, 나머지는 밝은 문서형. (**미니멀 / 문서형**이 기본값)
- 최종 제출은 **PDF**도 준비 — 고정 렌더러는 인쇄(Ctrl+P → PDF 저장)용 스타일을 포함합니다.
