# 상세 기술문서 레이아웃 시안 (spikes/doc-layout)

`docs/design/portfolio-structure.md` §4-3의 세 시안(①②③)을 **실제 기술 문서**로 그려 보고, 지금 배포 중인 렌더러(A0)와 나란히 캡처한 시험대입니다. F6("상세 문서 레이아웃은 시안 3개 캡처를 보고 유지관리자가 정함")을 위한 R0.5 첫 작업입니다. **제품 코드가 아닙니다.**

- 내용은 `data/projects/<폴더>.json`과 `src/<폴더>/기술문서.md`만 씁니다. 새 문장·수치는 만들지 않았습니다(UI 글자만 더함).
- 레포의 `index.html`, `project.html`, `assets/`, `data/`, `src/`, `profile.md`, `docs/`, `spikes/deck/`는 **읽기만** 했습니다. `assets/common.js`(slug·정규화 함수)는 고치지 않고 그대로 불러 씁니다.
- 문서 처리는 `assets/project.js`의 `renderDoc`과 같은 순서·라이브러리·버전입니다: marked 12.0.2(gfm) → 상대경로를 `src/<폴더>/` 기준으로 → `PF.slugger`(GitHub식) 앵커·목차 → 절 연결 → Mermaid 11.4.1(`theme: 'default'`, `securityLevel: 'loose'`) → highlight.js 11.9.0(github-dark).

## 여는 법

`fetch()`로 데이터를 읽으므로 파일을 더블클릭하면 열리지 않습니다. **레포 루트**에서 로컬 서버를 띄웁니다.

```powershell
# 레포 루트(C:\Users\user\portfolio-test)에서
python -m http.server 4600          # python이 없으면 py -m http.server 4600
```

- 시안 ②(임시 추천): http://localhost:4600/spikes/doc-layout/doc.html?layout=2
- 시안 ①: `…/doc.html?layout=1`, 시안 ③: `…/doc.html?layout=3`
- 지금 렌더러(A0)와 비교: http://localhost:4600/project.html?p=1-action-platformer#pf-doc

| 주소 옵션 | 효과 |
|---|---|
| `?p=<폴더>` | 프로젝트(기본 `1-action-platformer`). `0-Tidy-Mommy`, `2-Yggdrasil`도 열림(오류 0 확인). 데이터가 없는 폴더는 "프로젝트를 찾을 수 없습니다" |
| `?layout=1\|2\|3` | 시안 선택(기본 2) |
| `&narrow=1` | ③을 [좁게 읽기] 켠 상태로 시작(버튼으로도 전환, 이 브라우저에만 기억) |
| `#sec=<절 제목>` | 요약 덱에서 오는 딥링크 형식(§3-3). 제목을 찾아 정규 앵커 `#<slug>`로 바꾸고 2초 강조. 예: `#sec=4.3%20핵심%20동작` |
| `&pf-footnotes=0` | 인쇄용 링크 각주·링크 목록 끄기 |

공통 틀(설계값, §4-3): 목차 260 · 간격 40 · 본문 칸 · 간격 40 · 레일 300(**1800px 이상에서만**), 바깥 패딩 `clamp(16px, 2.5vw, 48px)`. 1200px 미만은 목차를 숨기고 아래쪽 [목차] 서랍, 720px 미만은 휴대폰 한 열.

모든 시안 공통:
- **머리 막대**: `← 포트폴리오 ↗ › 제목 — 기술 문서` + [요약 덱으로 ↗] [GitHub ↗] [시연 영상 ↗] + "링크는 새 탭에서 열립니다". 본문 칸 맨 위에 h1(= 프로젝트 제목)·한 줄 소개·메타·태그.
- **목차**(왼쪽, 고정): H2·H3, 지금 위치 강조(`aria-current="location"`), 요약 덱에 실린 절에 ★ + 숨김 "(요약 덱에 있음)".
- **레일**(≥1800px, 고정): 이 프로젝트(메타·링크) / 지금 읽는 절(그 절이 요약 덱 장면이면 장면 칩) / 원문 마크다운 ↗ · 원문 GitHub ↗ · 맨 위로.
- **절 머리 칩** `◧ 요약 덱의 이 장면 · 핵심 구현 1/4 · <항목 제목> ↗`: `highlights[].section`·`troubleshooting[].section`이 가리키는 제목 바로 뒤. 주소는 `../deck/pages/project.html?p=<폴더>#s=hl-<n>` / `#s=ts-<n>`. 휴대폰에서는 작게 접고 "요약 덱은 PC에서 보기 좋습니다".
- **링크(F10)**: 외부·문서 사이·md 안 상대 파일은 `target="_blank" rel="noopener"` + ↗ 아이콘 + 숨김 "(새 탭)". 목차·md 안 `#앵커`·건너뛰기·맨 위로·라이트박스·`mailto:`는 같은 탭. md 안 `../<폴더>/<문서>.md#…`는 `doc.html?p=<폴더>#…`로.
- **접근성**: 건너뛰기 링크, `header`·`nav[aria-label=문서 목차]`·`main`·`aside[aria-label=요약 덱 연결]`, 코드·표는 `role=region tabindex=0`(코드 `aria-label="코드 (C#)"`), Mermaid SVG `role=img` + 이름 + `<details>다이어그램 원문</details>`, `prefers-reduced-motion`.
- **라이트박스**: 그림 클릭, 다이어그램 [크게 보기](원래 크기, 손가락 확대 허용).
- **A4 인쇄**(§4-8): 목차·레일·칩·머리 막대·↗ 숨김, 코드는 밝은 테마 + 줄바꿈, `pre`·표 행·그림·도식 `break-inside: avoid`, 제목 `break-after: avoid`, 바깥 링크는 각주 번호 + 문서 끝 링크 목록.

## §4 설계와 다르게 한 곳

| # | 무엇 | 이유 |
|---|---|---|
| 1 | 칩은 "H2마다"가 아니라 **data가 가리키는 제목 바로 뒤**(이 문서에서는 H3 7곳) | §4-5 규칙. `section` 값이 모두 H3 제목입니다. 회고(`retro.section`)는 data에 없어 칩 없음(§3-3 대체 동작) |
| 2 | 덱 링크 조각은 설계 계약 `#s=hl-<n>`·`#s=ts-<n>` | 지금 덱 시안(`spikes/deck`)은 이 id를 몰라 **1장으로 열립니다**(그 시안은 `#n`과 제목 id만 앎). 덱 시안은 쓰기 범위 밖이라 고치지 않았습니다 |
| 3 | 레일 "지금 읽는 절" 카드를 넣음 | 이번 작업 요청. §4-5에서는 R1.5 항목 |
| 4 | 720~1799px에는 "한눈에" 상자를 두지 않고, 메타는 h1 아래 줄·링크는 머리 막대에 둠. "한눈에"는 휴대폰에서만(접힘) | 머리 막대와 같은 링크가 두 번 나오는 것을 피함 |
| 5 | 새 탭 표시는 ↗ SVG + 숨김 글자 "(새 탭)"(`.sr-only`), 인쇄에서는 둘 다 숨김 | 이번 작업 요청. §5-3의 `aria-describedby` 방식과의 비교(NVDA·PDF 텍스트 층)는 **미확인** |
| 6 | Mermaid 전에 Pretendard를 먼저 받음(최대 4초), SVG `width`를 원래 폭(viewBox)으로 고정 | 글꼴이 늦으면 노드 글자 폭이 어긋남. 폭을 고정해야 `fit-content` 그림 상자가 원래 크기를 압니다. A0는 기다리지 않음 |
| 7 | 코드 스크롤 상자를 `<code>`가 아니라 `<pre>`로, 안쪽 여백 18/20px | A0는 hljs CSS가 뒤에 실려 `<code>` 여백이 1em(13.5px)이 되고 `<code>`가 스크롤됩니다. `role=region`을 `<pre>`에 주려고 바꿈. 가로로 더 있을 때만 오른쪽을 흐리게(mask) |
| 8 | 반응형 규칙을 `@media screen`으로 한정 | A4 인쇄 폭(약 680px)에서 휴대폰 규칙이 켜지지 않게 |
| 9 | 인쇄 각주·링크 목록을 `beforeprint`가 아니라 처음 그릴 때 인쇄 전용으로 만들어 둠 | 헤드리스 `printToPDF`에서도 같은 결과. `beforeprint` 발생 여부와 무관 |
| 10 | 인쇄 첫 줄의 웹 주소는 지금 주소(`location`) | data에 `site.baseUrl`이 아직 없음. 그래서 이 PDF에는 `127.0.0.1:4651` 주소가 찍힘(§5-4 문제 그대로) |
| 11 | 페이지 배경 흰색, "← 포트폴리오"는 `../../index.html` | 카드가 없어진 본문(§4-4)에서 표·도식이 회색 위에 뜨지 않게. 포트폴리오 덱은 아직 없음 |
| 12 | 캡처는 `prefers-reduced-motion: reduce`로 | 부드러운 스크롤·도착 강조를 꺼서 캡처를 결정적으로. GIF는 캡처마다 다른 프레임 |

## 눈여겨볼 점 (판단 재료)

- **②**는 바깥 빈칸이 가장 작고(1920 48, 2560 201) 코드·표가 모두 들어가며 도식 축소는 같거나 가장 적습니다(1366 4/9로 같음, 1920 3/9, 2560 0/9). 대신 **문단만 있는 구간은 오른쪽이 비고**(1920 529, 2560 864px, 캡처 (e)), **그림도 원래 크기까지 커져서** 첫 화면을 대표 이미지가 거의 채웁니다(1920 1169px, 2560 1400px, 캡처 (a)).
- **①·③**은 2560에서 바깥 빈칸이 다시 401px입니다(빨간 선 문제가 그대로). 1920에서는 81px.
- **③**은 문단 옆 빈칸이 가장 작지만(168) 한 줄이 길어집니다. [좁게 읽기]는 ①과 같은 모양이 됩니다.
- 휴대폰은 세 시안이 같은 한 열이라 차이가 없습니다(A0보다 본문 칸이 38px 넓음).
- ② A4 PDF는 38쪽, 빈 쪽 0입니다. 큰 도식을 통째로 다음 쪽에 넘기면서 아래가 반쯤 비는 쪽이 있습니다(예: 4·11쪽). F3대로 잘림 방지만 하고 빈칸 0은 보장하지 않는 결과입니다.
- md 원문의 `**"…"**를`처럼 따옴표로 시작·끝나는 굵게는 A0와 시안 모두 굵게가 되지 않고 `**`가 그대로 보입니다(marked의 CommonMark 규칙, 같은 파이프라인이라 같은 결과). 이번 범위 밖입니다.

## 미확인

- 헤드리스 Chrome 155에서만 쟀습니다. 창이 있는 Chrome·Edge, Edge 헤드리스, Windows 배율 125%(2560 화면의 CSS 폭 2048)는 확인하지 않았습니다.
- 브라우저 확대 200%·400%, NVDA·내레이터, 닫힌 `<details>`(다이어그램 원문) 안의 Ctrl+F 펼침.
- 인쇄 `break-after: avoid`·`break-inside: avoid`: 몇 쪽(1·8·13·37쪽 등)을 눈으로 봤을 때 제목이 다음 블록과 함께 있고 코드가 쪽 사이에서 잘리지 않았지만, 38쪽 전수 검사는 하지 않았습니다. 한 쪽보다 큰 코드·도식이 어떻게 나뉘는지도 확인하지 않았습니다.
- 요약 덱 링크 `#s=hl-<n>`이 실제 장면으로 가는지(덱 시안이 지원하지 않음).
- 캡처는 Switch Strike 하나입니다. 다른 두 샘플은 렌더 오류 0만 확인했습니다.
